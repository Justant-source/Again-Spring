## 1. 제품 정의 & 디자인 철학

### 1.1 한 줄 정의

> **"분쟁을 혼자 끙끙 앓지 않고, 스스로 또는 갈등 당사자와 함께 풀어간다.
> 익명 여론 투표로 여러 시선을 빌린다."**

- 핵심 컨셉: **광장형(Town Square)** — 사연을 익명 광장에 올리고, 작성자 vs 상대방 공감 투표·댓글을 받는다.
- 타깃: 20~40대 한국 사용자. 연인·부부·친구·가족·직장 갈등.
- 철학: **판결이 아니라 시선.** "다름"을 "잘못"으로 만들지 않는다. 공감 비율은 *평결*이 아니라 *어느 입장에 더 공감이 가는지*다.

### 1.2 설계 4원칙 (반드시 준수)

1. **간단·직관.** 한 화면에서 색·배치만으로 의미를 알 수 있어야 한다. 장황한 안내 문구 금지.
2. **색으로 말한다.** 작성자 = 피치, 상대방 = 세이지. 이 의미는 앱 전체에서 일관 유지한다.
3. **AI식 과잉 설명 금지.** "~하면 두 입장이 나란히 놓여요" 같은 군더더기 설명 박스를 쓰지 않는다. 라벨·색·레이아웃으로 대체한다.
4. **익명 기반.** 모든 사연·댓글·투표는 익명 닉네임으로 노출된다.

## 2. 디자인 언어 한눈에 (Look & Feel)

다시봄의 인상은 **"이른 봄의 미스트 세이지"**다. 차갑지 않은 옅은 청록빛 회녹색을 바탕에 깔고, 그 위에 잘 정돈된 편지지처럼 넉넉한 여백과 세리프 제목을 얹는다. 화면은 떠들지 않는다. 색이 말한다 — **작성자는 따뜻한 피치, 상대방은 차분한 세이지.** 두 색은 좌·우 위치가 고정되어 "누구의 입장인가"만 가리킬 뿐, 옳고 그름을 뜻하지 않는다.

감정이 실리는 자리(사연 제목·본문)에는 **명조 세리프**를, 기능을 다루는 자리(버튼·라벨·통계)에는 **산세리프(Noto Sans KR)**를 쓴다. 굵기는 500을 넘지 않아, 어디에도 소리치는 글자가 없다. 모서리는 입력·탐색 화면에선 거의 각지고(편지지), 결과·리포트 화면에선 둥글다(따뜻한 결과지). 하트·무지개·마스코트·네온은 없다. 전체적으로 **조용하고, 단정하고, 따뜻한 광장.**

세 가지 톤을 화면 성격별로 쓰되 **절대 섞지 않는다.**

| 톤 | 별칭 | 용도 | 인상 |
|---|---|---|---|
| **Tone L** | 편지지(Letter) | 입력·탐색·작성·대기·인증·마이·알림 | 잘 정돈된 편지지 |
| **Tone P** | 파스텔(Pastel) | 결과 리포트(혼자/함께/마감) | 따뜻한 결과지 |
| **Tone Q** | 조용한 고급감(Quiet) | (향후) PDF 리포트·프리미엄·상담사 연결 | Linear / Arc Browser |

## 3. 색 시스템

> 모든 값은 `frontend/app/globals.css`의 런타임 토큰(`:root` CSS 변수)을 정본으로 한다. 색은 항상 **CSS 변수**로 참조하고, 하드코딩하지 않는다.

### 3.1 Tone L — 편지지 (입력·탐색·작성 계열)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--L-bg` | `#EDF1E8` | 배경 (미스트 세이지) |
| `--L-card` | `#F7F9F2` | 카드 |
| `--L-ink` | `#2E3A2E` | 본문 텍스트 (그린 잉크) |
| `--L-sub` | `#7C8A77` | 보조 텍스트 (세이지 그레이) |
| `--L-border` | `#D3DCC9` | 보더 |
| `--L-point` | `#8A3A1F` | 포인트 (테라코타 — 링크·강조 극소량) |

### 3.2 Tone P — 파스텔 (결과·리포트 계열)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--P-bg` | `#EFF4EA` | 배경 |
| `--P-card` | `#F7FAF2` | 카드 |
| `--P-ink` | `#2E3A2E` | 본문 |
| `--P-sub` | `#7C8A77` | 보조 |
| `--P-border` | `#D3DCC9` | 보더 |
| `--P-a` | `#C9785A` | **작성자 진영색(피치)** — §3.4와 동일 |
| `--P-b` | `#5F8F76` | **상대방 진영색(세이지)** — §3.4와 동일 |

> Tone L과 Tone P는 잉크·보조·보더를 공유한다. 차이는 **배경의 미세한 온도**와 **라운드**(L=각짐, P=둥금)다. 즉 광장과 결과지는 같은 봄의 공기 안에 있다.

### 3.3 Tone Q — 조용한 고급감 (향후 / 제한적)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--Q-bg` | `#FAFAF7` | 배경 (오프화이트) |
| `--Q-card` | `#FFFFFF` | 카드 |
| `--Q-ink` | `#1A1A1A` | 텍스트 |
| `--Q-sub` | `#9B9890` | 보조 |
| `--Q-border` | `#E8E6E0` | 보더 (얇게) |
| `--Q-point` | `#6B7A8F` | 포인트 (블루그레이 1색) |

> 현재 광장형 코어에는 사용처가 없다. PDF 리포트·프리미엄 결제·상담사 연결이 도입될 때 사용한다.

### 3.4 진영색 — 작성자(피치) ↔ 상대방(세이지) · 가장 중요한 시각 언어

다시봄의 정체성. 점(dot)·라벨·막대·카드 배경·선택 테두리에 일관되게 쓴다. **작성자는 항상 왼쪽(피치), 상대방은 항상 오른쪽(세이지).**

```
작성자(피치 · 좌)   기본 PEACH = #C9785A   배경 PEACH_BG = #F6E6DD   선택테두리 PEACH_DK = #A55C3E
상대방(세이지 · 우) 기본 SAGE  = #5F8F76   배경 SAGE_BG  = #E6EFE8   선택테두리 SAGE_DK  = #487961
```

| 토큰 제안 | 값 | 용도 |
|---|---|---|
| `--faction-author` | `#C9785A` | 작성자 점·라벨·막대·텍스트 (= `--P-a`) |
| `--faction-author-bg` | `#F6E6DD` | 작성자 카드 배경 |
| `--faction-author-dk` | `#A55C3E` | 작성자 **선택 상태** 테두리(2.5px) |
| `--faction-partner` | `#5F8F76` | 상대방 점·라벨·막대·텍스트 (= `--P-b`) |
| `--faction-partner-bg` | `#E6EFE8` | 상대방 카드 배경 |
| `--faction-partner-dk` | `#487961` | 상대방 **선택 상태** 테두리(2.5px) |

**규칙**
- 선택 상태 테두리는 반드시 더 짙은 색(`_dk`)을 **2.5px**로.
- 피치/세이지는 "옳고 그름"이 아니라 **누구의 입장인지**를 가리키는 **중립 식별색**이다. 좌=작성자/우=상대방 위치 고정으로 식별을 보강한다.
- **금지:** 빨강/초록처럼 "정답·오답" 연상을 일으키는 색이나, 한쪽을 우월하게 보이게 하는 강조.
- 과거 결과지에서 쓰던 옅은 살구/세이지(`#F4A896` / `#A8C8B4`)는 **폐기**한다. 진영색은 위 6토큰으로 단일화한다.

### 3.5 톤 적용 규칙

| 화면 계열 | 톤 |
|---|---|
| 입력 · 탐색(광장) · 작성 · 대기 · 인증 · 마이페이지 · 알림 · 신고 | **Tone L** |
| 결과 리포트(혼자/함께/마감) · 상대 답변 도착 | **Tone P** |
| (향후) PDF · 프리미엄 · 상담사 연결 | Tone Q |

**한 화면에서 톤을 섞지 않는다.** 진영색(피치/세이지)은 톤과 무관하게 두 계열 모두에서 동일하게 쓴다.

### 3.6 구현 정합성

- **토큰 구현 위치**: `frontend/tailwind.config.ts` (theme.extend.colors) + `frontend/app/globals.css` (:root)
- **진영색 CSS 변수**: `--faction-author*` (피치) / `--faction-partner*` (세이지)
- **진영색 Tailwind**: `colors.author.*` / `colors.partner.*`
- **금지**: 색상 하드코딩. 반드시 CSS 변수 또는 Tailwind 토큰으로 참조.
- 코드와 이 문서가 어긋나면 **런타임 토큰(globals.css) 값이 최종 진실**이며, 이 문서를 그에 맞춰 갱신.

### 3.7 Tailwind 매핑 가이드 (Next.js 14 구현)

`tailwind.config.ts`의 `theme.extend.colors`에 CSS 변수를 그대로 노출해 SSOT를 단일화한다. `:root`(globals.css)가 값의 정본, Tailwind는 별칭일 뿐이다.

```ts
// tailwind.config.ts (발췌 · 예시)
colors: {
  L: { bg:'var(--L-bg)', card:'var(--L-card)', ink:'var(--L-ink)',
       sub:'var(--L-sub)', border:'var(--L-border)', point:'var(--L-point)' },
  P: { bg:'var(--P-bg)', card:'var(--P-card)', ink:'var(--P-ink)',
       sub:'var(--P-sub)', border:'var(--P-border)' },
  author:  { DEFAULT:'var(--P-a)', bg:'#F6E6DD', dk:'#A55C3E' },
  partner: { DEFAULT:'var(--P-b)', bg:'#E6EFE8', dk:'#487961' },
}
```

## 4. 타이포그래피

```
@import 'Noto Sans KR' (300, 400, 500, 700) + 'Noto Serif KR' (400, 500, 600) — Google Fonts 단일 URL
--font-serif: 'Noto Serif KR', 'Nanum Myeongjo', serif
--font-sans : 'Noto Sans KR', -apple-system, system-ui, 'Malgun Gothic', sans-serif
```

| 역할 | 폰트 | 비고 |
|---|---|---|
| 사연 제목 · 본문(감성) | **세리프** (`--font-serif`, weight 500) | `letter-spacing: -0.01em` |
| 시적 인용구 | 세리프 **이탤릭** | 제안 문장 등 |
| UI · 라벨 · 버튼 · 통계 | **Noto Sans KR** (`--font-sans`, 400/500) | — |

**크기 스케일(px)**

| 용도 | 크기 |
|---|---|
| 랜딩 대제목(세리프) | 30 |
| 사연 제목 | 18~20 |
| 결과 제목 | 19 |
| 본문 | 12.5~15 |
| 라벨·메타 | 11~13 |
| 탭바 라벨 | 10 |
| 통계 숫자(세리프) | 22 |

**금지**
- `font-weight: 700` 및 bold 혼용 — **최대 500.**
- 한국어 Title Case / ALL CAPS — 자연스러운 문장형으로.

## 5. 형태 — 라운드 · 여백 · 그림자

| 항목 | Tone L | Tone P |
|---|---|---|
| 기본 라운드 | 3~8px (거의 각짐) | 12~18px (둥금) |
| 진영 카드 / 요약 박스 | 12px | 12~14px |
| 버튼 | 3~4px | 14px |
| 화면 좌우 패딩 | 20~26px | 20~26px |

- 여백은 넉넉하게. 편지지의 정돈된 호흡을 유지한다.
- 그림자는 거의 쓰지 않는다. 예외: 탭바 중앙 글쓰기 FAB(`0 4px 14px rgba(43,43,43,.28)`), 폰 프레임 외곽.
- **금지:** 3D 글래스모피즘, 네온, 무지개·강한 그라데이션. (페이드용 미세 그라데이션은 하단 버튼 영역에만 허용)

## 6. 시그니처 요소 (4종 · 일관 유지)

1. **진영색 식별** — 작성자 피치(좌) / 상대방 세이지(우). 점·라벨·막대·카드·테두리 전반.
2. **양면 투표 막대(VoteBar)** — 피치:세이지 합 100. 결과지(big)에선 `%` 표기, 카드 하단 미니 막대는 숫자 없이 색 비율만.
3. **기표 도장** — 투표 완료 표식. 대한민국 기표 도장(점복 卜)을 **SVG**로 구현(원 + 세로획 + 우상향 점획), 피치색, 라벨 "투표함". *한자 글자 `卜` 사용 금지 — 반드시 SVG.*
4. **메타포 일러스트(v15 라이브러리)** — 빈 상태·마케팅용. `viewBox 0 0 240 240`, stroke 1.5~2, 일러스트당 최대 3색(크림 `#FFF8F0` + 웜브라운 `#A08670` + 포인트). 자연물 은유.

## 7. 핵심 인터랙션 규칙

1. **인라인 투표(사연 상세).** 진영 박스 탭 = 그 진영 선택(짙은 `_dk` 테두리 2.5px + "· 선택됨"), 하단 비율 막대가 부드럽게 갱신. **"투표 완료하기" 버튼으로 확정.** 언제든 다른 박스 탭으로 변경 가능. 박스 안의 **"더 보기 ›"는 투표와 분리**(stopPropagation → 전문 읽기로 이동).
2. **투표 완료 표식.** 우상단 기표 도장 SVG + "투표함". 별도 결과 페이지로 이동하지 않는다.
3. **게시.** `/community/new`에서 원문 게시 후 투표·댓글이 핵심 상호작용이다.
4. **상대 초대 자동 합류.** "먼저 올리기" 시 단독 공개 후, 상대 답변 도착하면 오른쪽(세이지)에 자동 추가.
5. **미응답 단독 게시.** 대기 화면에서 "지금 혼자 올리기" 가능.
6. **댓글 진영 표시.** 작성자/상대방 댓글은 `* 닉네임` + 진영색(피치/세이지). 일반 유저는 검정 닉네임, 별표 없음. BEST 댓글은 상단 고정.
7. **게스트 제약.** 글·투표·댓글 O / 초대·수정·이력·알림 X → 가입 유도 바텀시트(`C3_GuestSheet`).
8. **전역 탭바.** `광장 / 알림(뱃지) / ＋글쓰기(중앙 FAB) / 내 활동`. **입력·결과·세션·인증 화면에서는 숨겨** 몰입을 유지한다.

## 9. 카피 & 톤 규칙

- **존댓말 기본.** 따뜻하고 차분하게.
- 가정형: "~하셨을 수 있어요", "~처럼 느끼셨을 것 같아요".
- **양쪽 호명 순서 균형** (작성자를 먼저 말했으면 다음엔 상대방 먼저).
- 헤드라인은 짧고 시적: "내 갈등, 혼자 판단하기 어려울 때.", "이 사연, 어떻게 올릴까요?"
- **공감 비율은 '평결/판정'이 아니라 '시선'으로.** "작성자에 공감이 더 모였어요"(O) / "작성자가 옳다고 판결했어요"(X).
- 모든 사연·댓글 길이 제한 **600자.**

- ❌ Duolingo식 마스코트 캐릭터
- ❌ "과실비율", "판결", "유죄/무죄", "가해자/피해자", "회피형", "나르시시스트" 등 **판결/병리 용어** ([forbidden-words.md](../../shared/70-policy/forbidden-words.md) 참조)
- ❌ 다크모드 기본값 (미스트 세이지의 따뜨함과 충돌)
- ❌ 3D 글래스모피즘, 네온, 강한 그라데이션
- ❌ `font-weight: 700` 혼용 (최대 500)
- ❌ 한국어 Title Case / ALL CAPS
- ❌ **AI식 과잉 설명 박스** (색·라벨·배치로 대체)
- ❌ 진영색(피치/세이지)을 옳고 그름·우열로 사용
- ❌ 투표 도장에 한자 글자 `卜` 직접 사용 (SVG로만)
- ❌ 네이버·카카오 소셜 로그인 (이메일 + Google만)

- **이모지 사용 금지** (잠금 표시 등 불가피한 경우 최소한, 가능하면 SVG로 대체).

- 카탈로그: [icons.md](./icons.md)

## 14. 접근성 (최소 기준)

- 본문 텍스트(`--L-ink`/`--P-ink` on bg)는 WCAG AA 본문 대비를 만족하도록 유지한다.
- **색만으로 의미를 전달하지 않는다.** 진영 구분은 색 + 위치(좌/우) + 텍스트 라벨("작성자"/"상대방")을 항상 동반한다.
- 탭·버튼 터치 타깃은 최소 44×44px 권장.
