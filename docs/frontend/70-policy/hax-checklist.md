# HAX 컴포넌트 체크리스트 — 다시봄 광장형

> **이 문서의 위치**: [`principles.md`](./principles.md)의 AI 신뢰성 원칙을 **컴포넌트 단위 체크리스트**로 풀어낸 것입니다.  
> PR 리뷰, 새 컴포넌트 작성 시 이 문서를 따라 점검합니다.

> **현재 기준**: 2026-06-02 광장형 피벗 완료.  
> **참고**: Microsoft HAX Toolkit — [Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/)

---

## 1. 페이지 레벨 체크리스트

### 피드 페이지 (`/community`)
- [ ] 게스트 열람 가능 (로그인 강제 없음)
- [ ] 무한스크롤 또는 페이지네이션 (카운트다운 표시 금지)
- [ ] 카테고리 필터 (선택 안 함도 가능)

### 사연 작성 (`/community/new`)
- [ ] 로그인 필수 (미로그인 시 로그인 모달로 유도)
- [ ] 관계 카테고리 선택
- [ ] 제목·본문 텍스트카운팅 (제한선 있으면 진행 상태 표시)

### 사연 상세 (`/community/[id]`)
- [ ] 투표 비율: 실제값만 표시 (임의값 금지)
- [ ] 작성자/상대방 진영색 일관
- [ ] 댓글 섹션: 로그인 미작성 사용자는 댓글 아이콘에 로그인 유도
- [ ] 위기 컨텐츠: 클라이언트 모달 없음 — `CrisisKeywordGuard.scan` 감지 시에도 게시는 그대로 진행, 서버 감사 로그(`com.againspring.safety.audit`)만 남음

### 알림 (`/notifications`)
- [ ] 읽음 처리 후 30일 자동 삭제 (UX: 명시)

## 2. 코어 컴포넌트 체크리스트

### FeedCard
**역할**: 사연 카드 (피드 목록에 표시)

#### 기본 정보
- [ ] 제목 표시
- [ ] 카테고리 표시
- [ ] 작성자 닉네임 (익명) 표시
- [ ] 날짜/시간 표시

#### AI 신뢰성 (HAX G1, G2, G6)
- [ ] AI-user 콘텐츠가 보이면 AI 레이블/구분 유지
- [ ] 작성자/상대방 색상 구분 (피치/세이지) 일관 적용
- [ ] 공감 비율 표시 (실제값만)

#### 접근성
- [ ] `data-testid="feed-card-{id}"` 부착
- [ ] 이모지 하드코딩 없음
- [ ] 모바일 반응형

---

### VoteBar
**역할**: 작성자 vs 상대방 공감 비율 막대

#### 정확성 (HAX G2, G11)
- [ ] 작성자/상대방 비율: 실제 집계값만 표시
- [ ] 백분율 또는 실수치 명시
- [ ] "이 비율은 커뮤니티 투표 결과입니다" 명시

#### 시각화
- [ ] 작성자: 피치(#C9785A), 상대방: 세이지(#5F8F76) 일관 유지
- [ ] 투표 전/후 상태 구분 (아이콘, 색상 짙기 등)

#### 접근성
- [ ] `data-testid="vote-bar-{post_id}"` 부착
- [ ] 색깔만으로 구분 아님 (숫자·텍스트 라벨도 있음)

---

### CommentBar
**역할**: 댓글 목록 (무한스크롤)

#### 기본
- [ ] 댓글 작성자 닉네임 (익명) 표시
- [ ] 댓글 본문
- [ ] 작성 시간
- [ ] 좋아요 수

#### 안전성
- [ ] 댓글에 표현 필터 미적용 (사용자 책임)
- [ ] 위기 키워드 있으면 관리자 플래그 (UX: 해당 댓글에 경고 표시 옵션)

#### 접근성
- [ ] `data-testid="comment-{comment_id}"` 부착
- [ ] 무한스크롤: 로딩 상태 명시 (스켈레톤 또는 "더 불러오는 중...")
- [ ] 이모지 하드코딩 없음

---

### CommentComposeSheet
**역할**: 댓글 작성 입력창

#### 기본
- [ ] 로그인 미사용자: 컴포즈 비활성화 + "로그인해주세요" 메시지
- [ ] 로그인 사용자: 입력창 활성화
- [ ] 전송 버튼 ("댓글 게시" 등 명시적 라벨)

#### 안전성
- [ ] 입력 길이 제한 있으면 카운팅 표시 (진행 상태 표시, 타이머 아님)
- [ ] 표현 필터 미적용 (사용자 입력 책임)
- [ ] 제출 후 입력창 초기화

#### 접근성
- [ ] `data-testid="comment-compose-sheet"` 부착
- [ ] 이모지 추가 버튼 없음 (이모지 금지)

---

### CommunityComment (개별 댓글 컴포넌트)
**역할**: 댓글 단일 항목

#### 기본
- [ ] 작성자 닉네임 (익명) 표시
- [ ] 댓글 본문
- [ ] 작성 시간
- [ ] 좋아요 버튼 (로그인 필요)

#### 안전성
- [ ] 위기 키워드 표시 (관리자만 보임)

#### 접근성
- [ ] `data-testid="community-comment-{id}"` 부착

---

### UserChip
**역할**: 사용자 정보 칩 (닉네임, 권한 표시)

#### 기본
- [ ] 닉네임 표시
- [ ] 권한 레이블 (예: "작성자") 있으면 표시
- [ ] 아바타 (있으면)

#### 접근성
- [ ] `data-testid="user-chip-{user_id}"` 부착

---

### BrandBar
**역할**: 앱 헤더/네비게이션

#### 기본
- [ ] 로고 표시
- [ ] 메인 네비게이션 (피드, 알림, 프로필 등)
- [ ] 로그인/로그아웃 버튼

#### 안전성
- [ ] 위기 상황 핫라인 링크 (상시 표시, 관리자 설정 시 강조)

#### 접근성
- [ ] 모든 네비 버튼: `data-testid` 부착
- [ ] 키보드 포커스 가능

---

### SideStory
**역할**: 사이드 패널 또는 추가 정보 카드

#### 기본
- [ ] 컨텐츠 명확한 라벨 ("투표 결과", "위기 자원" 등)

#### AI 신뢰성 (해당 시)
- [ ] AI 생성 컨텐츠면 "AI가 분석한 결과입니다" 명시

#### 접근성
- [ ] 닫기 버튼 명시 (모바일에서 스와이프/뒤로가기)

## 3. 상황별 체크리스트

### 위기 컨텐츠 처리
- [ ] 클라이언트 위기 모달 없음 — 광장형 정책상 게시는 차단하지 않는다
- [ ] `CrisisKeywordGuard.scan` 감지 시 `CrisisDetectedEvent` → 서버 감사 로그(`com.againspring.safety.audit`, 본문 비노출)만 기록

### 색상 일관성
- [ ] A측 (작성자): 피치 계열 (`var(--faction-author)` 또는 `var(--P-a)`)
- [ ] B측 (상대방): 세이지 계열 (`var(--faction-partner)` 또는 `var(--P-b)`)
- [ ] 중립 (커뮤니티): 회색 계열
- [ ] 피치/세이지을 A/B 이외의 의미로 사용 금지

### 필터 미적용 원칙
- [ ] 사용자·AI 모두 표현 필터 미적용 (AI는 LLM 오류 문자열만 차단)

### 데이터 속성 (e2e 테스트)
- [ ] 모든 주요 상호작용 요소: `data-testid` 부착
- [ ] 변경 시 `tests/e2e-realbe/support/selectors.ts` 동기화 필수
