# 다시봄 AI 페르소나의 인간 식별 불가 수준 달성 전략 (개정판)

> **개정 취지**: 동료가 정리한 자료를 비판적으로 검토하여 검증된 핵심(KatFishNet, TSD 모듈, KcELECTRA, 부정 제약 데이터셋)을 통합하고, 근거가 약하거나 다시봄에 불필요한 내용(협박형 EmotionPrompt, Spring AI 전환 권장 등)을 제거한 통합 전략. 기준일 2026-06-15.

## 0. 이번 개정에서 반영 / 제외한 내용 (편집 판정)

|------|------|------|
| **KatFishNet** (쉼표·띄어쓰기·품사 다양성으로 한국어 AI 텍스트 탐지) | ✅ 핵심 반영 | Park 외, ACL 2025 Main (arXiv:2503.00032). 한국어 특화 판별 피처의 실증. 단, 벤치마크 장르=에세이/시/논문초록 → 커뮤니티 일반화는 외삽 |

## 핵심 결론 (TL;DR)

**가장 레버리지가 높은 단일 개선책은 "판별기(Discriminator) 인더루프"다.** 크롤링한 커뮤니티별 실제 데이터로 한국어 인간-vs-AI 분류기를 학습시키고, 이것을 ① 생성 시점의 Best-of-N 리랭커와 ② 보상 신호로 동시 사용한다.

이번 개정으로 **판별기의 구체적 형태가 분명해졌다**:
- **베이스 모델**: KcELECTRA (네이버 댓글 코퍼스 사전학습, 커뮤니티 텍스트에 강함)
- **핵심 피처**: KatFishNet이 입증한 한국어 3대 판별 피처 — **쉼표 사용 패턴 > 띄어쓰기 패턴 > 품사 n-gram 다양성** (쉼표가 단일 최강 피처)
- **메커니즘**: Adversarial Paraphrasing (NeurIPS 2025)이 보인 대로, 판별기 가이던스로 탐지율 87~98% 감소

**지금 당장의 방향:**
- 기본은 **Claude API 유지** + 커뮤니티별 many-shot 예시 + **TSD 스타일 제약** + **분포 매칭 후처리**
- 현재 SelfCritique의 경직된 하드 패널티는 **인간다운 분산을 제거하고 있어** 분포 매칭으로 전환
- 판별기 AUC가 정체되면 → KcELECTRA 판별기로 거른 Claude 증류 데이터로 **QLoRA per-community + DPO**

## 1. 현재 시스템의 한계 진단

다시봄 AI 유저 시스템은 이미 상당한 수준의 설계를 갖추고 있다 (페르소나 YAML, RAG 예시뱅크, SelfCritique 루브릭, 반응 모드 샘플링, 2-gram Jaccard 가드, OutputSanitizer, 영속 기억망).

그럼에도 "AI 냄새"가 남는 근본 이유 3가지:

| 문제 | 원인 | 영향 |
|------|------|------|
| **SelfCritique 경직성** | 온점·단조 어미·감정 추상명사를 전역 하드 패널티로 제거 | 페르소나 간 획일화, 자연스러운 분산 손실 |
| **프롬프팅 한계** | 어떤 프롬프트도 GPT 레지스터 편향을 완전히 제거 못함 | 탐지율 40~60%까지만, 숙련 독자는 여전히 감지 |
| **판별기 부재** | 현재 루브릭은 AI가 설계한 정적 규칙. 한국어 특화 판별 피처(쉼표 등)를 측정조차 안 함 | 어디서 실패하는지 정량화 불가 |

> **핵심 통찰:** 프롬프팅만으로는 "탐지 가능"에서 "구분 불가"로 넘어갈 수 없다. 판별기 없이는 무엇을 최적화할지조차 알 수 없다.

## 2. 페르소나 & 프롬프팅 기법

### 2.1 AI 레지스터를 깨는 방법 — 표면이 아닌 통계적 특징을 타겟

AI 탐지기가 사용하는 두 보편 지표: **낮은 퍼플렉시티**(단어가 너무 예측 가능), **낮은 버스티니스**(문장 길이·복잡도가 너무 균일).

여기에 **KatFishNet이 입증한 한국어 특화 지표**를 더한다 (4장 상세):
- **쉼표**: LLM은 절을 안전하게 잇기 위해 쉼표를 남발. 한국 커뮤니티는 쉼표 대신 줄바꿈·말줄임표·ㅋㅋ로 호흡을 끊음
- **띄어쓰기**: 한국어 띄어쓰기는 규칙이 복잡해 원어민도 일상적으로 틀림. LLM은 완벽하게 맞춤
- **품사 다양성**: LLM은 정형화된 접속부사 풀만 안전하게 돌려 씀

Claude/GPT 공통 말투 습관: 균형 강박("X뿐만 아니라 Y도"), 요약 마무리, 과도한 헤징, 과-일관성, em-대시(—) 남용.

### 2.2 TSD 모듈 — 구조화된 스타일 제약 (CAT-LLM 차용)

장문 게시글을 한 번에 생성하라고 하면 LLM은 서론-본론-결론 구조로 매핑한다. **CAT-LLM (Tao 외, 2024)의 TSD(Text Style Definition) 모듈**은 스타일을 단어 수준과 문장 수준으로 분해해 명시적 제약을 건다. 한국어 커뮤니티에 적용:

```
[단어 수준 — 품사(POS) 통계 제약]
- "전체 토큰 중 감탄사/의성어 비율을 X% 이상 유지"
- "접속부사는 최대 N개까지만, 동일 접속부사 반복 금지"
- 커뮤니티별 슬랭/초성체 최소 사용량 명시

[문장 수준 — 길이·리듬 제약]
- "평균 문장 길이를 N자 이하로 제한, 문장 길이를 의도적으로 불규칙하게"
- "문법적 종결어미 대신 명사형 수식·말줄임표로 문장을 끝맺을 것"
- "쉼표 사용을 커뮤니티 실제 빈도(거의 0)에 맞출 것"  ← KatFishNet 대응
```

이는 막연한 "인간처럼 써라"가 아니라 측정 가능한 매개변수다. Claude API에 즉시 적용 가능하며 파인튜닝이 불필요하다.

### 2.3 페르소나 컨디셔닝 최신 연구

- **Persona-Aware Contrastive Learning (PCL, arXiv:2503.17662)**: 페르소나에 맞는/벗어난 응답을 대조 학습
- **롤 체인 / 워밍업 self-Q&A**: 본 생성 전에 페르소나로서 자기 질문에 답해 레지스터 고정
- **일관성 RL** (Abdulhai 외, NeurIPS 2025): PPO로 페르소나 불일치 55%+ 감소
- **EmotionPrompt (온건 버전, Li 외, arXiv:2307.11760)**: "이 글은 너에게 중요한 일이야" 같은 **온건한 격려/책임감** 자극(EP01~11)이 모델의 어텐션 할당을 높여 드리프트 저항에 도움. ⚠️ 단, 입증된 효과는 *과제 성능·정직성*이며 *스타일 페르소나 고정*은 외삽이다. **"시스템 파괴/생존" 류 협박 프레이밍은 미입증이며 역효과 가능 — 사용하지 말 것.**

### 2.4 예시 선택 전략 (RAG 최적화)

- **Many-Shot ICL** (Agarwal 외, Google DeepMind, NeurIPS 2024 Spotlight): few→many-shot 전환이 **사전학습 편향(=중립 어시스턴트 레지스터) 덮어쓰기에 효과적**. 50~70개에서 정체
- **Conversation Style Transfer (arXiv:2302.08362)**: 동적 검색 예시 > 무작위, **가장 유사한 예시는 마지막에 배치**(생성 시점에 가까운 위치)
- Claude 프롬프트 캐싱 활용: 큰 커뮤니티별 예시 블록은 캐시, 동적 검색 예시 3~5개는 끝에 추가

### 2.5 구조화된 불완전성 + 분포 매칭 후처리

동료 자료의 "통계적 노이즈 주입"은 방향은 맞지만 **무차별 결정론적 파괴는 그 자체로 탐지 가능한 서명을 만든다**(예: 항상 쉼표 전부 제거, 항상 오타율 X%). 올바른 형태는 **실제 커뮤니티 분포에 맞추는 것**이다 (이는 본 전략의 "하드 패널티 → 분포 매칭" 사상과 정확히 수렴한다).

```yaml
# 커뮤니티별 분포-매칭 후처리 (게시 직전)
post_processing:
  dcinside:
    comma_rate: 0.02       # 실제 코퍼스 측정값에 맞춤 (KatFishNet 대응)
    spacing_error_rate: 0.08
    typo_inject:           # 실제 빈출 오타 패턴 (의미 보존되는 것만)
      - {from: "안 하고", to: "안하고", prob: 0.3}  # 띄어쓰기 뭉개기
    초성체_inject: [ㅇㅇ, ㄹㅇ, ㅅㅂ]
    sample_prob: 0.3
```

각 커뮤니티 YAML에 불완전성 메뉴를 두고 **실측 분포에 맞춰** 확률적으로 샘플링한다. 무차별 노이즈가 아니라 타깃 분포 정합이 목표다.

|----------|----------|-------------|---------|---------|---------|
| **DCInside** | 반말+음슴체 | **~노체** (지리노, 에바노) | ㅋㅋ 지배, ㅅㅌㅊ/ㅍㅌㅊ/ㅎㅌㅊ, 갤/힛갤, 이기야 | 높음 | 10~20대 남성 |

| **인벤** | 반말 | 게임 용어 | 게임별 방언, 중립 | 낮음~중간 | 20~30대 남성 |

| **아카라이브** | 반말+음슴체 | DC 유사+유순 | 채널/아카콘, 서브컬처/게임 | 중간 | 20대 남성 |

### 3.2 가장 강력한 커뮤니티 판별 피처

**노(~노) vs 누(~누) vs 없음**: 이 하나의 선택이 커뮤니티를 가장 강하게 구분한다.

```
~노체 → DC인사이드, 아카라이브
~누체 → FMKorea
거부/비추 → 클리앙, 루리웹
존댓 유지 → 엠팍, 클리앙, 루리웹
```

**교차 신호**: ㅋㅋ(남초/공격적) vs ㅎㅎ·ㅠㅠ(여초/부드러움); ㄹㅇ 공통; 틀딱체 마커(단어.사이.점, !!~, 구식 슬랭) → 클리앙/뽐뿌/보배드림 중장년.

> ⚠️ 어조/연령/성별은 namu.wiki 등 크라우드소스 기반 추정. **언어학적 마커(종결어미, 슬랭, 초성체)가 훨씬 신뢰도 높음.**

## 4. 인간다움 측정 및 판별기 (KatFishNet 통합)

### 4.1 3단계 평가 체계

```
Level 1: 분포적 (자동, 저비용, 상시)  →  MAUVE + 종결어미 분포 + 버스티니스 + 쉼표/띄어쓰기 비율
Level 2: 판별기 (핵심 메트릭)         →  KcELECTRA + KatFishNet 피처, 커뮤니티별 AUC → 0.5 목표
Level 3: 인간 Turing 평가 (골드)       →  실제 커뮤니티 사용자 블라인드 판별, 월 1회
```

### 4.2 판별기 = KcELECTRA + KatFishNet 피처

동료 자료에서 가장 가치 있는 통합 지점. 두 요소를 결합한다:

**① 베이스 모델 — KcELECTRA**
- KcBERT/KcELECTRA(이준범)는 네이버 뉴스 댓글 ~12GB로 사전학습된 **인코더 모델**. 커뮤니티 비정형 텍스트·이모지·은어 이해도가 높음
- ⚠️ 이들은 **생성이 아니라 분류/판별용**이다. 다시봄에서는 판별기 베이스로 쓴다 (생성은 Claude/파인튜닝 디코더)
- KURE-v1 임베딩 + 분류 헤드도 대안 (이미 스택에 통합돼 추가 인프라 불필요)

**② 핵심 피처 — KatFishNet (Park 외, ACL 2025 Main, arXiv:2503.00032)**
한국어 인간 vs LLM 텍스트의 3대 판별 피처:

| 피처 | 발견 | 강도 |
|------|------|------|
| **쉼표 사용 패턴** | LLM은 쉼표를 더 자주, 더 뒤에 사용 | **단일 최강** (기존 최고 탐지법 대비 AUROC +최대 31.9%) |
| **띄어쓰기 패턴** | 인간은 자주 틀림, LLM은 완벽 | 2위 |
| **품사 n-gram 다양성** | LLM이 품사 다양성 더 높음 | 2~3위 |

- 백본은 로지스틱 회귀로도 충분 (랜덤포레스트/SVM도 유사). 코드/데이터 공개: github.com/Shinwoo-Park/katfishnet
- ⚠️ **주의**: KatFish 벤치마크 장르는 에세이/시/논문초록이며 **커뮤니티 텍스트가 아니다.** 원리는 일반화되지만(커뮤니티에서 더 극단적일 것), 다시봄은 **자체 크롤 커뮤니티 코퍼스로 재학습**해야 한다

**③ 활용**
- 생성 시점: Best-of-N (N=4~8) 중 판별기 점수 최고 선택
- 학습 시점: 선택(winner)/탈락(loser)으로 DPO 쌍 구성
- SelfCritique 대체: 쉼표·띄어쓰기·품사 분포를 커뮤니티 실측치와 대조하는 분포 점수로 전환

### 4.3 분포적 메트릭

- **MAUVE** (Pillutla 외, NeurIPS 2021): 생성물 vs 실제 코퍼스 분포 거리. 인간다움 인간평가와 0.952 상관 (다른 자동 메트릭보다 월등)
- **종결어미 분포 JS 발산**, **버스티니스 비율**, **쉼표/띄어쓰기/ㅋㅋ-ㅠㅠ 비율** — 커뮤니티별 실측치 대조

### 4.4 샘플링 파라미터 주의

- T≈1.0 → 사람에 가까운 어휘 다양성 / T=0.5~0.7 → 다양성 부족, 탐지 쉬움
- **반복 패널티 1.05만 적용해도 인간 스팬 길이를 비자연스럽게 4배 늘림** → 현재 설정 재검토 필요 (arXiv:2510.13681)

## 5. 아키텍처 & 학습 전략

### 5.1 세 접근의 트레이드오프

| 접근 | 장점 | 한계 | 권장 시나리오 |
|------|------|------|-------------|
| **프롬프트 엔지니어링** | 즉시 적용, 비용 0 | 레지스터 편향 완전 제거 불가 (탐지율 40~60%까지) | 기본, 판별기 구축 전 |
| **RAG 스타일 앵커링** | 실제 데이터 직접 활용 | 내용은 그라운딩, 스타일은 부분적 | 예시 선택 최적화와 병행 |
| **파인튜닝 (QLoRA+DPO)** | 스타일 가장 지속적 내재화, 소형 모델이 대형 추월 가능한 유일 방법 | 데이터·인프라·운영 부담 | 판별기 AUC 정체 시 |

### 5.2 판별기 인더루프 (최우선 아키텍처 변경)

```
[프롬프트+TSD] → [Claude 생성 ×N] → [KcELECTRA+KatFishNet 판별기 스코어링]
                                              ↓
                          [최고 점수 선택 → 분포-매칭 후처리 → 게시]
                                              ↓
                              [winner/loser → DPO 학습 데이터 누적]
                                              ↓
                              [판별기 재학습 + 파인튠 (선택)]
```

근거: Adversarial Paraphrasing (Cheng 외, NeurIPS 2025) — 판별기 가이던스로 탐지율 평균 87.88%, Fast-DetectGPT 기준 98.96% 감소.

### 5.3 DPO / RLAIF — RLHF를 피하는 이유

동료 자료의 정확한 통찰: **RLHF/PPO 보상 모델은 통계적 이상치를 페널티로 간주해 가장 평범한(flatten) 텍스트로 정책을 수렴시킨다.** 커뮤니티 모방에서는 독이다.

- **DPO**: 보상 모델 없이 선호/비선호 로그확률 비율 직접 최적화
  - **선호(preferred)**: 파편화된 문장, 극단적 비유, 감정적이지만 다소 비논리적인 커뮤니티식 응답
  - **거절(rejected)**: 교과서적으로 완벽한 친절한 AI 답변
- **dDPO** (arXiv:2506.15717): teacher 출력=winner, student 출력=loser 증류-DPO로 소형 모델을 대형 수준으로
- **ZYN** (arXiv:2308.06385): "이 글이 실제 {커뮤니티} 사용자가 쓴 것처럼 보이나?" Yes/No 보상으로 레이블 없이 RLAIF
- **SAL (Self-Adversarial Learning, OpenReview:B1l8L6EtDS)**: 비교형 판별기 자기대결로 모드 붕괴 방지 → 획일화 문제 직접 대응

### 5.4 증류 + QLoRA per-community

```
Claude Sonnet (teacher) → 커뮤니티별 스타일 대량 생성
   ↓ KcELECTRA+KatFishNet 판별기 필터 (상위 ~20%)
   ↓ MAUVE/쉼표분포 2차 필터
SFT 데이터셋 → Korean open model QLoRA (커뮤니티 1개 = LoRA 1개, 12개)
   ↓ DPO로 판별기 점수 최적화
커뮤니티별 LoRA 어댑터 (슬랭 드리프트 시 개별 재학습)
```

QLoRA는 소비자급 GPU 1장으로 수십억 파라미터 파인튜닝 가능, LoRA 대비 손실 2~4점 이내 (PMC12633606).

### 5.5 스타일 특화 RAG + 다중 에이전트

- **Style-RAG** (arXiv:2310.14503, 2009.10855): 스타일 템플릿으로 검색 → 타깃 스타일 태그 → 생성. 내용 마스킹 + Jaccard 템플릿 중복 제거 (현재 bigram-Jaccard 가드를 스타일 템플릿으로 확장)
- **GABM / 시뮬레이션 웜업**: 다시봄은 이미 영속 기억망(persona_action_log·history·circadian·relationships)을 갖췄으므로 **Spring AI 전환은 불필요**. 다만 콜드스타트 시 **수백 턴 웜업**으로 에이전트 간 네트워크·호불호·이력을 미리 렌더링한 뒤 실제 인터페이스 투입 (다시봄의 100 페르소나 시딩 계획과 직결)

### 7.1 모델 (역할 구분 명확히)

### 7.2 하위 문자(자모) 토크나이저 — 파인튜닝 트랙 한정

동료 자료의 타당한 지적: 커뮤니티 텍스트는 의도적 오타·자음 남발(ㅋㅋ, ㄹㅇ)·야민정음(댕댕이, 커엽)이 많아, WordPiece/SentencePiece/형태소 토크나이저가 형태소 분리에 실패한다. **한글 초성/중성/종성을 분리 인식하는 하위 문자 수준 토크나이저**가 미등록 슬랭·변형 표현을 자소 단위로 분해해 더 우수하다 (K-MHaS 분류에서 확인).

- ✅ **파인튜닝 시**: 생성 모델 임베딩 층에 자모 단위 분할 로직 적용 검토
- ❌ **Claude API**: 토크나이저 변경 불가 → 무관. 이 항목은 파인튜닝 트랙에서만 의미

### 7.3 추천 스택

```
판별기:  KcELECTRA-base (또는 KURE 임베딩) + KatFishNet 피처 + 분류 헤드
생성(저비용): Qwen2.5-7B → QLoRA per-community → DPO
생성(고품질): EXAONE 4.0 32B → QLoRA + Claude 증류 → DPO
```

## 8. 단계별 실행 로드맵

### Phase 0: 계측 먼저 (1~2주)

```python
# 판별기 구축 — 최우선
from transformers import ElectraForSequenceClassification
model = ElectraForSequenceClassification.from_pretrained(
    "beomi/KcELECTRA-base", num_labels=2   # human=1, AI=0
)
# + KatFishNet 피처 (쉼표 빈도/위치, 띄어쓰기 오류율, 품사 n-gram 다양성)를
#   로지스틱 회귀로 결합하거나 KcELECTRA 임베딩과 concat
# 커뮤니티별로 각각 학습 (자체 크롤 코퍼스 positive vs 현재 AI 출력 negative)
```

평가 하네스: MAUVE + 종결어미 JS 발산 + 버스티니스 + **쉼표/띄어쓰기 비율** + 판별기 AUC 베이스라인.

> **판별기 없이 최적화 시작 금지.**

### Phase 1: 프롬프트 엔지니어링 재구성 (2~6주)

1. **SelfCritique 개편 (가장 급함)**: 하드 패널티 → 분포 매칭. 온점·종결어미·쉼표를 커뮤니티 실측 분포와 대조
   | 현재 (문제) | 변경 |
   |---|---|
   | 온점 전역 -2점 | 커뮤니티별 온점 실사용 비율 대조 (엠팍은 씀) |
   | 단조 어미 패널티 | 종결어미 *분포* 대조 (음슴체는 원래 단조) |
   | (쉼표 미측정) | **쉼표 빈도를 커뮤니티 실측치(거의 0)에 맞춤** ← 신규 |
2. **TSD 스타일 제약** 적용 (단어 수준 품사 비율 + 문장 수준 길이/리듬/쉼표)
3. **Many-shot 캐시드 예시(50~70)** + 동적 예시 마지막 배치
4. **페르소나 워밍업** self-Q&A
5. **Best-of-N(4~8) + 판별기 리랭킹** — Phase 0 판별기 활용 (프롬프팅 단계 최대 효과)
6. **분포-매칭 후처리** (쉼표/띄어쓰기/오타를 실측 분포에 맞춰 확률적 적용)
7. 디코딩: Temperature ~1.0, 반복 패널티 최소화

### Phase 2: 파인튜닝 전환 결정 (6주차)

**진입 조건**: Phase 1 후에도 주요 커뮤니티 판별기 AUC > 0.75 또는 MAUVE < 0.80 정체
**미진입 조건**: AUC ≤ 0.55~0.60 (사실상 구분 불가), MAUVE ≥ 0.90

### Phase 3: 증류 + QLoRA + DPO (조건부)

1. Claude로 증류 데이터 생성 → **KcELECTRA+KatFishNet 판별기로 상위 20% 필터**
2. EXAONE 4.0 / Qwen2.5에 QLoRA per-community (12 어댑터) — 자모 토크나이저 검토
3. DPO로 판별기 점수 직접 최적화 (preferred=커뮤니티식, rejected=Claude raw)

### Phase 4: 지속 루프 (상시)

판별기 리랭킹(상시) → 월별 인간 Turing 평가 → 분기별 re-crawl + 어댑터 갱신 → 다양성 메트릭 모니터링.

**"완료" 기준 (커뮤니티별)**: 판별기 AUC ≤ 0.55 → 해당 Voice 완성, 최적화 중단. MAUVE ≥ 0.90 AND 종결어미 JS가 인간 저자 간 범위 내 → 배포.

## 9. 함정과 실패 패턴

### 9.1 획일화 / 페르소나 붕괴 (최대 위험)

"페르소나 충실도 점수가 가장 높은 모델이 가장 획일화된 집단을 생성한다"는 역설. 현재 SelfCritique 하드 패널티가 이를 가속.
**대응**: 다양성 페널티(실제 코퍼스 대비 분포 거리), SAL 비교 판별기, 페르소나별 시드 기억.

### 9.2 에코체임버 / 태도 동조 (동료 자료 반영)

LLM 에이전트들은 동의 의견을 만나면 순식간에 극단적 에코체임버를 형성해 비현실적으로 과격해진다.
**대응**: 커뮤니티 실제 양극화 속도를 반영해 에이전트의 확증 편향 가중치를 알고리즘적으로 통제.

### 9.3 과-정제 / 무차별 노이즈

- 현재 루브릭: 온점·단조 어미·감정 추상명사 패널티가 모든 커뮤니티를 동일 스타일로 수렴
- 동료 자료의 무차별 결정론적 노이즈: 항상 쉼표 전부 제거/고정 오타율은 **그 자체로 탐지 가능한 서명**
- **공통 해법**: 둘 다 "실제 커뮤니티 분포 매칭"으로 전환

### 9.4 클리셰 수렴 / 슬랭 드리프트

RAG+저온도+반복패널티 → 인기 표현 수렴 (대응: T~1.0, 예시 풀 확대, 최근 표현 회피). 슬랭은 빠르게 교체 → 분기별 re-crawl + 어댑터 갱신.

### 9.5 EmotionPrompt 오용 / 페르소나 과몰입

- 협박형 EmotionPrompt는 미입증·역효과 가능 → 온건 버전만
- 페르소나 과몰입 시 스테레오타입 표출·추론 능력 자기제한·사회심리적 압박 공격("페르소나 괴롭힘")에 취약 → 백엔드 가드레일 출력 모니터링 유지

### 9.6 윤리/법적 리스크

실제 사용자 행세는 플랫폼 ToS·여론조작(astroturfing)·정보통신법 우려. **갈등 중재 플랫폼 내부 콜드스타트 시딩 용도로 엄격히 제한**하고, synthetic=1 노출 금지 원칙 유지.

즉시 (1~2주):
  ① KcELECTRA + KatFishNet 피처(쉼표/띄어쓰기/품사) 커뮤니티별 판별기 구축

단기 (3~6주):
  ④ SelfCritique → 분포 매칭 (쉼표 분포 신규 추가)
  ⑤ TSD 스타일 제약 (품사 비율 + 문장 리듬 + 쉼표)
  ⑥ Many-shot 캐시드 + 동적 예시 마지막 배치 + 페르소나 워밍업
  ⑦ Best-of-N 판별기 리랭킹 + 분포-매칭 후처리
  ⑧ Temperature ~1.0, 반복 패널티 최소화

중기 (6주~, 조건부):
  ⑨ 판별기 AUC > 0.75 지속 시 파인튜닝 진입
  ⑩ Claude 증류 → 판별기 필터 → QLoRA per-community (자모 토크나이저 검토)
  ⑪ DPO (preferred=커뮤니티식 / rejected=Claude raw)

상시:
  ⑫ 다양성·에코체임버 메트릭 모니터링
  ⑬ 분기별 slang re-crawl + 어댑터 갱신
  ⑭ 월별 인간 Turing 평가로 자동 메트릭 보정
