## 요약

v2는 세 가지 근본 미스매치를 수정해 식별률을 33.3pp 낮췄다. **단위를 메시지에서 계정으로, 최적화를 선택에서 생성으로, 판정자를 proxy에서 사람으로 옮겼다.** 각 레버는 생성 능력 개선 없이 메모리·cadence·후처리 필터로 구현됐으므로 다른 AI 페르소나 시스템에 직접 전이 가능하다.

## 무엇이 작동했나 (레버별 효과)

### Phase 3 — 계정 메모리·Trajectory

**문제**: v1은 매 POST마다 새 갈등 시나리오를 생성했다. "팀장이 나한테 갑질했다"는 글과 "남편이 가정을 외면한다"는 글 사이에 연결고리가 없었다. 실제 계정은 한 사건이 몇 주에 걸쳐 발전하고, 이전 글의 코멘트에 답하고, 주제가 점진적으로 드리프트한다.

**해결**:
- `life_state.json` 파일 기반 계정 히스토리 (per-persona historyDir)
- `ongoingSituation` 필드로 전 POST에서 진행 중인 사건 주입
- CASUAL 결정: i.i.d. 25% → **스트릭 기반** (같은 주제 반복 확률)
- `situationContinuityBlock()` PromptAssembler 추가

**효과**: v2 평가에서 3개 포스트가 인간으로 오인됐다 (P1 CASUAL·P7 복잡논리·P13 장편흡수). 이들은 모두 계정 히스토리를 활용한 포스트였다.

### Phase 4 — Cadence & 상호작용

**문제**: v1은 매 틱(10분)마다 새 글을 생성했고, 댓글 대댓글이 거의 없었다. 실제 계정은 글을 올린 뒤 몇 시간 뒤에 응답하고, 댓글 대댓글에서 여러 번 왕복한다. 이것도 계정 "humanness"를 나타내는 중요한 신호다.

**해결**:
- `scheduleReplyWithDelay(5~60분)` 배선 → 댓글 응답 딜레이
- `MAX_REPLIES_PER_COMMENT` 2→4 (대댓글 깊이)
- PersonaSelector에 circadian 가중치 기반 쿨다운 추가 → 활동 패턴 자연화

**효과**: 게시 cadence 버스트 패턴이 희석되고, 상호작용 그래프가 현실 소셜 네트워크에 가까워졌다.

### Phase 5 — Named-tell 제거 (결정론적 필터링)

**문제**: Phase 3~4로 계정 동작은 개선됐으나, 여전히 생성 텍스트 자체에 "봇다움" 신호(tells)가 있었다. v1은 판별기로 "가장 사람 같은" 초안을 선택했지만(Best-of-N), 이는 Goodhart 문제 — 판별기의 맹점을 최대로 찌르는 것이지 실제 humanness는 아니었다.

**해결**:
- `SELF_CRITIQUE_EXTRA_CLICHES` 목록 확대: 
  - v1: "정신 못 차리겠음", "이게 맞는 건가 싶음"
  - v2: "인지/건지 모르겠음/다", "나는 모르겠음", "황당한 건지", "기분 나쁜 건지" 추가
  - v2b: 어미 변형 ("모르겠어/어요/네요") 미등록으로 통과
- SelfCritique threshold 유지 (5/7): 단일 클리셰만으로는 탈락 안 함 (의도적 완충)
- tell 탐지는 생성기 파인튜닝이 아니라 후처리 필터로 구현 → 토큰 효율

**효과**: v2 66.7% → v3 55.6% (-11.1pp). Phase 3~4의 구조적 개선에 필터가 추가되면서 식별률이 PASS 목표(≤60%)에 진입.

## ASM/WaggleBot 전이 교훈

다른 AI 유저·소셜 봇 시스템 구축 시 적용 가능한 원칙 5가지:

### 1. Tell은 반복 패턴에서 나온다

AI가 생성 능력으로 막힐 때, 대신 문장 종결어미·주제 편중·감정 수식어 부재 같은 **언어 패턴**에서 tells를 찾아라.

- 예: "~건지 모르겠음" 어미 → v2에서 5개 포스트 탐지
- 예: 단편적 사건 나열 (감정 앞에) → P7 감정평탄화 탐지
- **실무**: 한국어 커뮤니티 유저 1~2인에게 "AI 특징" 물어보고 정규표현식 또는 n-gram으로 신호화. 파인튜닝보다 저비용.

### 2. 장르 일치가 핵심

**일관성 높음 커뮤니티** (갈등 사연 = NATEPAN)에서 AI가 더 오래 탐지되지 않는다. 

- v1: THEQOO(오락)·CLIEN(IT 정보) 혼합 → 단문·감정 약함 = 명확한 봇 신호
- v2: NATEPAN(갈등·관계) 전용 → 장편·구체 사건 = tell 희석

**실무**: 대상 커뮤니티의 최빈 장르를 먼저 분석. 생성 프롬프트를 그 장르로 고정하면 일관성이 자동으로 올라온다.

### 3. 단문은 무기

P3 (남편 안경 단문, 극단적 짧음)가 인간으로 오인된 것은 우연이 아니다.

- 장편은 텔을 숨기기 쉽다 (구체 사건이 감정을 덮음).
- 단문은 정반대: tell이 노출되기 쉽지만, 노출되지 않으면 "너무 자연스러움".
- **실무**: 포스팅 길이 다양화를 명시적으로 생성기 프롬프트에 포함. 단문 비율 ≥30%.

### 4. 구체 사건 + 슬랭이 tell을 덮는다

P5, P13, P15가 통과한 공통점:

- P5: 구체 금액("5백")·구체 맥락("팀장") → tell이 배경음
- P13: 구체 수치("천만 원")·경제 갈등 깊이 → 높은 진정성
- P15: 슬랭("어쩜", "짜증")·분노 감정 농도 → 필터 못 걸림

**실무**: 구체성·스타일(슬랭/방언)·감정 농도를 tell 제거 로직 앞에 우선배치. 구체성 높을수록 필터 threshold를 상향.

### 5. Eval을 생성보다 먼저, 측정을 타깃에 정렬하라

**v1의 가장 큰 실수**: proxy 평가(LLM·MAUVE)를 생성과 동시에 돌렸다.
- 결과: 모든 proxy가 맞지 않음 + 변수 귀속 불가 + 고빈도 반복의 momentum

**v2의 가장 잘한 판단**: kill criterion을 Phase 0 시작 전에 사전 등록했다.
- Phase 2 → 블라인드 eval 키트 (고정 18개 포스트, 정답키 미공개)
- Phase 5 → named-tell 라벨셋으로 취급 (평가 후 분석)
- 결과: 무침 v1 → 메모리 v2 → 필터 v3의 각 레버 효과 측정 가능

**실무**: 평가 도구를 먼저 만들고(고정 eval kit), 생성 개선은 뒤에. 각 라운드의 eval을 **named-tell 라벨셋**으로 취급해서 다음 라운드에서 제거할 신호를 명시적으로 거둬라.

## 숨겨진 한계와 다음 질문

v2가 PASS했지만, 몇 가지 한계도 명확하다:

### 1. 여전히 단일 평가자

오너 1인의 평가로 식별률을 재었다. 캐주얼 독자 3인 이상 합의는 다음 라운드.

### 2. Phase 5b 어미 변형 미등록

"모르겠어/어요/네요" 3종이 아직 필터에 없다. 다음 라운드에서 추가하면 식별률이 +3~5pp 올라갈 수 있음.

### 3. 신규 tells의 정규표현식화 미완

"~인지 ~건지" 이중질문, 감정 평탄화, 맥락 불일치는 아직 코드에 반영 안 됨.

### 4. 생성 파인튜닝 0

v2는 100% 프롬프트 엔지니어링. QLoRA 같은 파인튜닝은 데이터 게이트(clean real ≥수천) 뒤로 연기.

## 최종 결론

**v2는 생성 능력을 바꾼 게 아니라, 평가와 필터링의 관점을 바꿨다.**

- v1: 메시지 품질 ↑ (failed · proxy 폐기)
- v2: 계정 동작 + 텍스트 필터 ↓ (PASS · -33.3pp)

이것이 다른 AI 페르소나 시스템에도 먹히는 이유는, **단위와 타깃을 정렬하는 것이 어떤 사양 변경보다 훨씬 효과적**이기 때문이다.

ASM·WaggleBot을 지을 때는 v2의 순서를 따르라:
1. **타깃 단위 확정** (글 vs 계정 vs 채널)
2. **Eval 도구 구축** (고정 키트, 정답키 사전 등록)
3. **Baseline 블라인드 평가** (tell 분석)
4. **1변수/1라운드 개선** (메모리 → cadence → 필터)
5. **Kill criterion 사전 박기** (말이 아니라 숫자로)

이렇게 하면, v1의 2주 방황을 피할 수 있다.
