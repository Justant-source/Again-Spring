## 요약

v2.1은 v2의 두 가지 측정 착시(오라클 오염, tell 생존)를 바로잡았다. 
- **v2 결함**: 오너 1인(봇헌터 수준) 평가 + 글 단위 + proxy MAUVE 부재
- **v2.1 재구성**: 신선 캐주얼 독자 ≥3인 + 광장별 계정 타임라인 + 카테고리 정렬 = 제품 적합성

Phase 5 FAIL(80% > 60%)로 T1·T3 제거 필요 확인됨. Phase 8 결과 봉인 전까지의 **선제 교훈 5가지**.

## 선제 교훈 (Phase 8 결과 무관)

### 1. 오라클 재정립: 오너 은퇴, 신선 캐주얼 ≥3인 패널로 교체

**교훈**:  
v2는 오너 1인이 55.6% PASS 판정을 내렸으나, 오너는 라운드를 거치며 패턴을 학습(봇헌터 수준)한 상태. 
이는 "다시봄 캐주얼 독자가 봇을 구분 못 하는가"를 검증하지 못했다.

**선택 근거**:  
- charter V2-D04 명제 A: 오너를 캘리브레이션 전용으로 강등
- evaluator-registry.md: 오너는 EXCLUDED from gate

**실무 적용**:  
- 게이트 평가자: 신선 캐주얼 독자 ≥3인 (회전 레지스트리로 기억 방지)
- 오너: 동일 키트를 별도 채점 (divergence 진단용, 게이트 판정 아님)
- 다음 라운드 어디서든: 기억 오염 = 신뢰도 -30~50pp → 평가자 재모집 필수

---

### 2. 단일 평가자 불안정성: 편차 60~80%, ≥3인 통합 평균 필수

**수치**:  
Phase 5 동일 키트(v2.1-phase5-01)에서:
- E-001(임슬기): 80% AI 식별
- E-002(박진수): 80%
- E-003(김철수): 80%
- E-S1(부정선거): **60%** (Phase 8 키트 오전달로 Phase 5 평가)

**편차 분석**: 60~80% = 20pp spread → 4인 평균 75% (여전히 FAIL)

**선택 근거**:  
- phase5/v2.1-phase5-01-result-supplement.md: E-S1 메모가 T1·T2(동일사건반복·미완종결)와 정확히 일치하나, Human 글도 "반복"·"오타"로 오탐 2건
- 단 1인 = 신뢰도 불충분

**실무 적용**:  
- 단일 평가자로 게이트 결정 금지
- 최소 3인 이상, 평균 식별률로만 kill criterion 판정
- 편차 분석: |Naive Avg - Owner| > 0.3 → 오너 방법론 검토 (진단용, halt 아님)

### 3. 키트 전달 프로세스 통제: 파일명(phaseN) 확인 + registry 기록 필수

**사건**:  
E-S1에게 Phase 8 대신 Phase 5 키트(`v2.1-phase5-01.html`)가 오전달.
- 결과: Phase 5 정답키로 평가됨 → 게이트 미반영 → 참고치로만 기록
- 근인: 파일명 미확인 + registry 선행 기록 부재

**선택 근거**:  
- evaluator-registry.md 표: E-S1 row에 "⚠️ Phase 8 키트 오전달" 명시됨
- 발송 전 파일명 검증 → evaluator-registry 기록 순서 → 링크 발송

**실무 적용**:  
1. 파일명에 phase number 명시 (예: `v2.1-phase5-01.html` vs `v2.1-phase8-01.html`)
2. 발송 전: evaluator-registry에 "발송 대상 키트" 사전 기록
3. 평가자 응답 수령 후: 회신된 키트 버전(HTML `<meta name="kit-id">` 또는 파일명)과 registry 비교 → 불일치 시 경고
4. 게이트 판정 전: 키트 오전달 여부 최종 확인

### 4. 제품 적합성 재구성: 광장 정렬 = 회피가 아닌 기능 가치

**교훈**:  
v2의 4개 미탐지(P3·P5·P13·P15)는 tell이 "제거"된 게 아니라 길이·구체성·슬랭으로 **묻혔을 뿐**.
회피 추격(whack-a-mole)을 계속하면 무한 루프.

**새 프레임**:  
다시봄은 6 광장(COUPLE·MARRIED·FRIEND·FAMILY·WORK·OTHER) 피드 구조.
- AI 사연을 광장에 정렬 → 각 광장 주제 일관성 상승 = **제품 가치**
- 맥락 불일치 tell 소멸 = 부산물 (정당화하지 말 것)
- "퇴행 금지": 회피 수준이 캐주얼 bar 거의 충족하므로 **더 추격하지 않는다**

**선택 근거**:  
- charter V2-D04 명제 B: "카테고리 정렬은 제품 적합성 프레임으로. 회피 정당화 금지."
- lessons.md "숨겨진 한계": v2도 생성 능력 한계 명시했음

**실무 적용**:  
- 분류 레버(예: NATEPAN 7,106건 → 6광장 분류)는 "호스트 글 다양성 향상"으로 정당화
- "봇 식별률 낮추기" 프레임 금지
- 교훈 문서: "광장 정렬로 맥락 불일치 tell이 소멸"을 성공 증거로 사용 OK
- 하지만 "회피 추격했다"는 표현 금지

## 최종 교훈 (결과 확정 후 채움)

### Phase 8 PASS 시 (`≤60%` 달성)

- [ ] **승리 명제 검증**: 광장 정렬이 신선 캐주얼 독자 ≥3인 기준으로 충족했는가?
- [ ] **계정별 강점/약점**: 어느 광장(COUPLE/MARRIED/FRIEND/FAMILY/WORK)이 강/약했는가? 계정 편차?
- [ ] **T1·T3 제거 효과**: Phase 5(80%) → Phase 8(≤60%)에서 정확히 얼마나 개선?
- [ ] **오라클 재정립 효과**: 오너(예상 95%+) vs 신선 ≥3인(≤60%) 격차 = 측정 착시 크기?

### Phase 8 FAIL 시 (`>60%`)

- [ ] **T1·T3 제거 불충분**: tell이 여전히 생성 스타일(코드)에 있는가, 아니면 맥락(카테고리 정렬 미흡)에 있는가?
- [ ] **광장별 효과**: COUPLE/MARRIED는 PASS, FAMILY/WORK는 FAIL 같은 불균형 있는가?
- [ ] **Phase 7 QLoRA 발동 여부**: 조건 3(광장별 clean ≥ 수백) 오너 임계 재확정 후 결정
- [ ] **v2 대비 해석**: v2 88.9%(오너 봇헌터 단독) → v2.1 신선 ≥3인(캐주얼) 비교 → 측정 방법론 신뢰도 평가
