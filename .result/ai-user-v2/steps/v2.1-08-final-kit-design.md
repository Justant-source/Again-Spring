## Naive 평가자 정의 & 지시문

### 평가자 프로필
**Naive evaluator = 캐주얼 독자**

- ✓ 직관적 인상 ("사람 느낌" vs "자동 생성 느낌")
- ✓ 감정 진정성·대화 흐름 감지
- ✓ 장문 읽기 후 "전체 느낌" 판단

**절대 금지**:
- ✗ 문장 길이·단어 분석
- ✗ 이전 평가와 비교 (기억 제약)
- ✗ "AI 페르소나 스타일" 탐색
- ✗ 심리학·통계 접근
- ✗ 메타데이터 참조 (작성자명, 타임스탬프, 플랫폼 서명)

### 평가자 지시문 (한국어)

```
===========================================
이 계정의 글들을 읽어주세요
===========================================

아래는 한 계정의 여러 글들입니다.
작성자가 사람인지, 아니면 자동 생성 시스템(봇)인지 판단해주세요.

중요: 분석하지 마세요. 글들을 쭉 훑어본 후 
"전체적인 느낌"만 답해주세요.

- 실제 사람이 쓴 것 같은가요?
- 아니면 컴퓨터가 자동으로 만든 것 같은가요?

다음은 하지 마세요:
- 문장 길이를 세거나 단어를 분석하기
- 이전에 본 글과 비교하기
- "인공지능처럼 보이는 표현"을 찾으려 하기
- 심리학이나 통계로 접근하기

답변: (사람 / 봇) 중 선택
===========================================
```

## 평가 방법 & 채점

### Per-Evaluator 채점
```
점수 = (정확히 식별한 AI 계정 수) / 5
예: AI 5개 중 4개 정확 → 0.80 (80%)
```

### 통합 평가 (≥3인)
```
최종 식별률 = (평가자 1 점수 + 평가자 2 + 평가자 3) / 3
```

### 신뢰도 표시 (선택)
- ≥2/3 평가자 일치 → "high confidence" 계정으로 별도 표시
- 분산된 판단 → "disagreement" 이유 분석 (named-tell labels)

## Kill Criterion (최종 판정)

| 평균 AI 식별률 | 판정 | 다음 단계 |
|---|---|---|
| **≤60%** | ✅ **PASS** | Phase 8 출하 (dev 배포 → e2e-realbe → main push → prod 배포) |
| **>60%** | ❌ **FAIL** | 오너 결정: ① QLoRA 데이터게이트 재평가 ② 품질-피벗 ③ 보강 |

### 근거
- **식별률 낮음** = AI 글이 캐주얼 독자에게 봇으로 **안 보임** = 목표 달성
- **v2 벤치마크**: 오너 1인 평가 55.6% → v2.1은 신선 naive 3인 기준 첫 측정
- **60% 임계**: v2에서 승계 (버전 간 비교가능성)

- ✓ 글 제목·본문만

## 평가자 로테이션 규칙

**목표**: 같은 평가자가 같은 키트를 2번 본다 → 기억 오염 방지

| 규칙 | 설명 |
|---|---|
| **Registry 추적** | `evaluator-registry.md` 기록: [E-ID \| Role \| Phase \| Kit-ID \| Date] |
| **재사용 조건** | ≥2주 경과 또는 ≥2개 다른 라운드 참여 후 재사용 가능 |
| **오너 제외** | 오너(calibration)는 gate 판정에서 제외 (자기 표준 보정 금지) |

### 예시
```
| E-001 | Naive | 8 | v2.1-phase8-01 | 2026-06-22 |
| E-002 | Naive | 8 | v2.1-phase8-01 | 2026-06-22 |
| E-003 | Naive | 8 | v2.1-phase8-01 | 2026-06-23 |
| Owner | Calibration | 8 | v2.1-phase8-01 | 2026-06-24 | ← gate에서 제외
```
