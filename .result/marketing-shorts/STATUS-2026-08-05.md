## 3. End-to-end 데이터 흐름 (상세)

### 3.1 AS → ASM brief

`MarketingJobService.createJob`:

- `authorBody` 전문, `topComments` 상위 2 (좋아요순), `metaphorId`, empathy, jury 등.
- Shorts는 댓글 ≥2 권장(WB/ASM에서도 검증).
- Idempotency: 플랫폼별 active job만 차단. **READY/FAILED 후 같은 post에 youtube_shorts 재생성 가능**.

### 3.2 ASM credentials → options

`app/domain/credentials.py` — `youtube_shorts`:

| key | 용도 |
|---|---|
| `client_id` / `client_secret` / `refresh_token` | YouTube OAuth |
| `channel_id` | 채널 |
| `tts_voice` | **본문·intro·클로징** 내레이터 (예: `yura`) |
| `comment_tts_voices` | 댓글 풀, **콤마구분 최대 5** (예: `manbo,manu`) |

`youtube_shorts_pipeline.py`가 credential을 brief에 주입 → `waggle_client._brief_to_payload`:

```text
options.ttsVoice
options.metaphorId
options.commentVoices   # JSON array string
options.videoGen=false
options.autoHdRender=true
```

`externalId` (WB `posts.origin_id`, **VARCHAR(128)** 로 확장됨):

```text
{postId}__voice_{tts}__meta_{metaphor|none}__cv_{sha1(comment_pool)[:8]}
```

옵션 변경 시 새 origin → 캐시된 RENDERED 잡 재사용 회피.

### 3.3 WB External ingest

`ExternalJobRequest.OptionsInput`:

```java
(Boolean videoGen, Boolean autoHdRender, String ttsVoice, String metaphorId, String commentVoices)
```

`ExternalIngestService`:

- 멱등: 같은 `(site_code, origin_id)` 이고 FAILED가 아니면 **기존 잡 반환** (재렌더 안 함).
- TTS voice 변경 시 FAILED로 강제 후 재적재.
- `variant_config`에 `tts_voice`, `metaphor_id`, `comment_voices`, `outro_text` 저장.
- again_spring outro 고정:
  - solo: `여러분의 의견을 댓글로 남겨주세요`
  - paired: `상대방의 사연이 궁금하면 댓글을 확인해주세요`

**강제 재렌더 운영법**:

```sql
-- WB DB (env-db-1 / wagglebot)
UPDATE posts SET status='FAILED', last_error='…', updated_at=NOW() WHERE id=…;
-- 필요 시 TTS 캐시 삭제
-- /app/media/tmp/tts_cache/*, /app/media/tmp/tts_scene_cache/{postId}/
-- /app/media/audio/again_spring/post_{origin_id}.wav
```

그 다음 AS에서 같은 post로 `youtube_shorts` 잡 재생성.

### 3.4 LLM + TTS + Render

`processor.llm_tts_stage` / `render_stage`:

1. 대본 (LLM 또는 재사용). again_spring은 본문 속 `type=comment` 제거(DB 댓글 씬만).
2. TTS 텍스트 = `ScriptData.to_narration_text()` = **hook + body only** (closer·댓글 제외).
3. Fish Speech 1회 → `content.audio_path`.
4. SceneDirector: intro / text_only… / comments / outro.
5. **본문·intro·outro** → narrator voice lock. **comments** → `comment_voices` 풀.
6. `render_layout_video_from_scenes(..., narration_audio=audio_path)`.

## 4. TTS / 오디오 설계 (핵심 개선)

### 4.1 통합 낭독 wav 재사용 (볼륨 점프 해결)

**문제(이전)**: LLM+TTS가 긴 wav를 만들어도, render가 장면마다 Fish Speech를 다시 호출 → 짧은 청크마다 음량·톤이 달라짐.

**해결**:

- `to_narration_text()`로 hook+body만 합성.
- `_generate_tts_chunks(..., narration_audio=)`가 hook/body 프레임을 **글자 수 비율로 atrim 분할**.
- closer / comments / chat만 개별 합성.
- `voice_override`를 청크별로 존중 (댓글 다른 목소리).

### 4.2 장면 분할 FFmpeg (중요 버그)

**버그**: `-i src -ss CURSOR -t SEG -af afade=...` 조합은 **cursor>0 조각을 무음(-91dB)** 으로 만듦.  
→ 본문 중간~끝이 통째로 무음. (job #447에서 재현: 5–25초 -91dB)

**수정**: filter graph만 사용:

```text
atrim=start=…:duration=…,asetpts=PTS-STARTPTS,afade=in,afade=out
```

코드: `worker/ai_worker/renderer/_tts.py` → `_split_wav_by_char_weights`.

### 4.3 AV 싱크

**하지 말 것**: 오디오 앞에 0.1s 무음(`adelay`) — “먹히는” 느낌.

**현재**: `TEXT_VISUAL_LAG_SEC = 0.1`  
정적 PNG concat 시 **직전 프레임을 0.1s 유지** 후 새 텍스트 표시. 오디오 타임라인 불변.  
파일: `layout.py`.

### 4.4 클로징 음량

**문제**: 짧은 outro에 1-pass `loudnorm` → 측정 붕괴(I≈-34 LUFS), 본문(-16) 대비 갑자기 작음.

**해결**:

- `_loudnorm_inplace`: **2-pass loudnorm** + 실패 시 **peak gain** (목표 TP≈-1.5).
- outro는 `MEDIA_DIR/audio/outro_cache/{voice}_{sha1(text)[:12]}.wav` 캐시.
- 캐시 히트 시에도 loudnorm 재적용(구캐시 교정).
- 통합 낭독 경로에서는 merge 시 `skip_global_loudnorm=True` (전역 loudnorm이 끝을 누르지 않게).

### 4.5 silenceremove 제거

`fish_client._post_process_audio`에서 `silenceremove` **완전 제거**.  
호흡/휴지를 무음으로 보고 본문을 잘라 **4초짜리 낭독**이 된 사고 있음.

현재 후처리: (optional atrim pad) → loudnorm → atempo(기본 1.2).

TTS 디스크 캐시 키: `md5(f"{voice}:{text}:pp_v3")` — 후처리 버전 바뀌면 키 변경 필요.

### 4.6 댓글 보이스

- AS FE: `CommentTtsVoicePicker` (체크 최대 5) → `comment_tts_voices` CSV.
- ASM → `options.commentVoices` JSON.
- WB `variant_config.comment_voices` → SceneDirector `_assign_comment_voice` (랜덤, narrator 제외 우선, 작성자 sticky).
- **again_spring “전 구간 단일 보이스” 강제 해제됨** (본문만 lock).

참조 폴더가 실제로 있는 키(2026-08-05 WB 호스트): **`yura`, `manbo`, `manu`** 정도.  
카탈로그에 `han`/`norah`/`anna` 등이 있어도 폴더 없으면 Fish가 기본 음색 → “여러 사람처럼” 들릴 수 있음. **풀에는 폴더 있는 키만**.

### WB 강제 재렌더

1. `posts.status='FAILED'`  
2. (필요) `tts_cache` / `tts_scene_cache` / `audio/again_spring/post_*.wav` / `outro_cache` 삭제  
3. AS에서 새 marketing job  
4. 로그 확인:
   - `narration wav 재사용: N frames`
   - `text visual lag=0.10s`
   - `2-pass loudnorm` / `peak gain`
   - `comment author … → voice=manbo|manu`
   - **`narration split` 후 중간 구간이 -91dB이면 atrim 회귀**

### 컨테이너 / 바이트코드 함정

`env-ai_worker-1`은 `worker` bind mount + **별도 `__pycache__` 볼륨**.  
소스만 고치고 restart 했는데 옛 동작이면:

```bash
docker exec env-ai_worker-1 find /app/ai_worker -type d -name __pycache__ -exec rm -rf {} +
docker restart env-ai_worker-1
```

Java(`ExternalJobRequest`) 변경은 **backend 이미지 rebuild** 필요 (`docker compose up -d --build backend`).

## 7. 버그·시행착오 타임라인 (학습용)

| 증상 | 원인 | 수정 |
|---|---|---|
| 장면마다 음량 들쑥날쑥 | 장면별 Fish 재합성 | 통합 wav + 분할 재사용 |
| 음성 0.1s 선행 | 싱크 불일치 | 텍스트 visual lag 0.1s (오디오 adelay 금지) |
| adelay 후 “먹히는” 소리 | 오디오 선무음 | adelay 제거 |
| 클로징 갑자기 작음 | 1-pass loudnorm short-clip 붕괴 | 2-pass + peak gain + 캐시 |
| 본문 4초만 / 잘림 | silenceremove가 호흡을 절단 | silenceremove 제거 (`pp_v3`) |
| 본문 중간 완전 무음 | `-ss` after `-i` + `afade` | `atrim`+afade |
| 댓글도 yura | again_spring 전구간 voice lock | 본문만 lock, comment pool |
| 재생성해도 옛 영상 | WB 중복 ingest (RENDERED) | FAILED 강제 또는 externalId 변경 |
| origin_id too long | `__cv_manbo-manu` 등 | `__cv_{sha8}` + VARCHAR(128) |
| 코드 반영 안 됨 | `__pycache__` 볼륨 | pyc 삭제 후 restart |

검증 잡 예시: `#436` 통합낭독, `#441` 댓글 보이스, `#442` visual lag, `#447` silenceremove 사고, **`#449` atrim 수정 정상**.

## 8. 다음 개선 제안 (다른 LLM용 백로그)

우선순위 제안:

1. **참조 음성 등록**  
   `prepare_voice.py`로 han/norah/anna 등 폴더 등록 → 댓글 풀 5개 실사용 가능.  
   UI에 “hasSample / ref_dir 존재” 배지.

2. **분할 타이밍**  
   글자 수 비율은 근사. 가능하면 whisper/VAD 또는 문장 경계 타임스탬프로 분할.

3. **outro loudnorm**  
   peak gain 폴백이 동작하나, 짧은 클립 전용 정규화(또는 본문 I에 맞춘 gain)를 더 단순화.

4. **Instagram Reels**  
   `instagram_reels`에 `tts_voice`만 있음. Shorts와 동일 WB 렌더를 reels 타깃으로 연결할지 제품 필요.

5. **AS prod FE**  
   댓글 TTS 피커는 **dev에 반영**. prod 어드민 UI는 prod 배포 지시 후. 현재 prod는 ASM API로 `comment_tts_voices` 설정됨.

6. **캐시 무효화 API**  
   “재렌더”를 FAILED SQL 없이 하는 admin/WB 엔드포인트.

7. **e2e**  
   Shorts는 LLM/GPU 의존 → realbe에서 스모크 범위 합의 필요. LLM 호출 금지 규칙 주의.

8. **메타포 intro**  
   `metaphor_id` PNG intro (이미 연결됨). 카탈로그·PLAN 매칭은 AS 쪽 이전 작업 참고.
