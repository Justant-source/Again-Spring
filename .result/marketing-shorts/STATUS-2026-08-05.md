## 4. TTS / 오디오 설계 (핵심 개선)

### 4.1 통합 낭독 WAV 재사용과 실제 발화 정렬

**문제(이전)**: LLM+TTS가 긴 wav를 만들어도, render가 장면마다 Fish Speech를 다시 호출 → 짧은 청크마다 음량·톤이 달라짐.

**해결**:

- `to_narration_text()`로 hook+body만 합성.
- `_generate_tts_chunks(..., narration_audio=)`가 hook/body 프레임을 faster-whisper `small` CPU `int8` 단어 타임스탬프와 원문 줄의 forced alignment로 구한 **실제 줄 시작 시각**에서 atrim 분할한다.
- closer / comments / chat만 개별 합성.
- `voice_override`를 청크별로 존중 (댓글 다른 목소리).
- #449의 26줄 narrator 검증은 alignment confidence `1.0`이었다. narrator 조각은 fade 없이 잘라 원래 순서로 재결합하며, 추가 lead를 제외한 원본 대비 peak/RMS `-inf dB`(sample-identical)를 확인했다.
- 운영 #454에서는 첫 narrator WAV의 native lead `0.118s`를 PCM으로 측정하고 부족한 `0.032s`만 보충했다. 최종 MP4의 첫 text→speech silence는 `0.149592s`였다.

### 4.2 장면 분할 FFmpeg (중요 버그)

**버그**: `-i src -ss CURSOR -t SEG -af afade=...` 조합은 **cursor>0 조각을 무음(-91dB)** 으로 만듦.  
→ 본문 중간~끝이 통째로 무음. (job #447에서 재현: 5–25초 -91dB)

**현재**: filter graph의 `atrim=start=…:duration=…,asetpts=PTS-STARTPTS`만 사용한다. 강제 fade는 사용하지 않는다.

```text
atrim=start=…:duration=…,asetpts=PTS-STARTPTS
```

코드: `worker/ai_worker/tts/alignment.py`, `worker/ai_worker/renderer/_tts.py` → `_split_narration_at_aligned_starts`.

### 4.3 AV 싱크

**하지 말 것**: 오디오 앞에 무음(`adelay`)을 넣어 화면을 맞추지 않는다 — “먹히는” 느낌을 만든다.

**현재**: 첫 narrator WAV는 native PCM lead를 `-45 dBFS`/3-frame 기준으로 측정해 150ms에 부족한 시간만 prepend하고 원본은 trim하지 않는다. 이후 text_only 줄은 오디오 타임라인을 바꾸지 않고 다음 실제 발화보다 150ms 먼저 나타난다. 사전 분할(`pre_split_lines`)도 한 번에 그리지 않고 plan entry 한 개씩으로 바꿔 `1 → 2 → 3`줄로 누적한 다음 다음 줄에서 초기화한다.
파일: `worker/ai_worker/renderer/layout.py`, `worker/ai_worker/renderer/_tts.py`.

### 4.4 클로징 타이밍과 캐시

outro를 단지 loudnorm으로 처리하는 것은 timing 계약을 보장하지 못한다. outro는 `MEDIA_DIR/audio/outro_cache/{voice}_{sha1(text)[:12]}.wav`에 캐시하고, renderer가 WAV의 선행 digital silence를 PCM `-45 dBFS` threshold/3-frame debounce로 측정한다. 마지막 댓글 발화 뒤 기존 화면을 250ms 유지한 뒤 outro text를 표시하며, lead가 150ms보다 짧으면 부족분만 prepend하고 음성/내부 휴지는 trim하지 않는다. 발화 뒤에는 500ms tail을 붙인다.

#449 solo Yura smoke에서 raw lead `0.095s`를 측정해 약 `0.055s`만 보충했다. 이 계약은 cached/generated WAV 모두에 적용된다.

### 4.5 silenceremove 제거

`fish_client._post_process_audio`에서 `silenceremove` **완전 제거**.  
호흡/휴지를 무음으로 보고 본문을 잘라 **4초짜리 낭독**이 된 사고 있음.

현재 후처리: 무음 단축 없이 loudnorm → atempo(`TTS_SPEED=1.1`) → 44100Hz mono.

TTS 디스크 캐시 키는 새 발음 반복에서 `voice:text:speed:pp_v5`다. 이 키는 이전 `pp_v4` 결과를
재사용하지 않는다. 이 반복은 production worker에 배포됐고, 정확한 narrator/scene-cache bypass로
final job `01KZ837XTDDX2P2MG90N42BM53`를 fresh 재생성·검증했다.

faster-whisper 모델 import 직전에 `config.settings.configure_huggingface_cache()`가 `HF_HOME`, Hub, Xet, XDG cache를 writable `WHISPER_DOWNLOAD_ROOT` 아래로 고정하고 `HF_HUB_DISABLE_XET=1`을 설정한다. 컨테이너 uid 1000의 `/.cache/huggingface/xet` 권한 실패를 피하기 위함이다.

### 4.6 새 한국어 발음 안정화 반복 (배포·fresh 검증 완료)

- `ScriptData.to_narration_text()`는 hook/body를 빈 줄 의미 블록으로 묶는다. 연결 어미로 끝난
  블록은 쉼표, 완결 블록은 마침표로 끝낸다. 화면용 `lines`는 바꾸지 않고 comment/closer는
  narrator 입력에서 제외한다.
- normalizer는 soynlp 반복 정규화를 물리 줄별로 적용해 빈 줄을 보존한다. Fish 요청은 문장
  구두점 → 의미 블록 → 공백 순서로만 분할하며, `TTS_MAX_CHARS_PER_REQUEST`를 맞추기 위해
  한국어 어절 내부를 hard slice하지 않는다.
- 길이가 정상인 충분히 긴 후보는 alignment와 같은 lazy shared faster-whisper `small` CPU `int8`
  모델/추론 lock으로 ASR 유사도·누락을 검사한다. candidate seed는 voice·정규화 대사·후보 번호로
  결정론적으로 생성하고 실제 ASR 실패에만 최대 2회 재합성한다. ASR 저신뢰·모델 오류는
  inconclusive로 수용하며, 소진 시 ASR 점수가 가장 높은 후보를 사용한다.
- Yura 32개 A/B는 baseline보다 개선된 파라미터를 찾지 못해 `voices.json` 파라미터를 변경하지
  않았다. 합법적으로 확인된 Yura reference는 1개뿐이며, 추가 reference는 화자 동의·원고가 있는
  새 녹음이 제공될 때까지 blocked다.
- `quality.py`의 `similarity < 0.35` AND `word coverage < 0.25` 규칙은 catastrophic
  low-confidence mismatch를 막는 방어 장치다. 배포는 완료됐지만 이 규칙을 FHD truncation의
  incident root cause로 해석하지 않는다. fresh raw/post-process/final narrator 검사는 모두
  통과했고 `atempo`는 원인 후보에서 제외됐다.

### 4.7 댓글 보이스

- AS FE: `CommentTtsVoicePicker` (체크 최대 5) → `comment_tts_voices` CSV.
- ASM → `options.commentVoices` JSON.
- WB `variant_config.comment_voices` → SceneDirector `_assign_comment_voice` (랜덤, narrator 제외 우선, 작성자 sticky).
- **again_spring “전 구간 단일 보이스” 강제 해제됨** (본문만 lock).

참조 폴더가 실제로 있는 키(2026-08-05 WB 호스트): **`yura`, `manbo`, `manu`** 정도.  
카탈로그에 `han`/`norah`/`anna` 등이 있어도 폴더 없으면 Fish가 기본 음색 → “여러 사람처럼” 들릴 수 있음. **풀에는 폴더 있는 키만**.

### WB 강제 재렌더

1. `posts.status='FAILED'`  
2. (필요) `tts_cache` / `tts_scene_cache` / `audio/again_spring/post_*.wav` / `outro_cache` 삭제  
3. AS에서 새 marketing job  
4. 로그/산출물 확인:
   - `narration wav 재사용: N frames`
   - `text visual lead=0.15s (audio unchanged)`
   - alignment confidence 및 첫/각 줄 시작 시각
   - `comment author … → voice=manbo|manu`
   - **aligned narrator split 뒤 원본 대비 음성 손상이 없어야 함**
   - `ffprobe` 기준 final MP4의 video/audio duration 차이가 30fps 한 frame 이내이고 tail/조기 video 종료가 없어야 함

> 이력: 2026-08-05 초기 운영 반영은 #454 이전 renderer 검증이었다. 이후 pp_v5와 canonical
> SceneDirector SD 기반 HD remux가 production에 반영됐고 dashboard worker 재시작 뒤 final job
> `01KZ837XTDDX2P2MG90N42BM53`를 fresh 검증했다. Shorts는 `autoPublish=false`이며 YouTube에
> 게시하지 않았다.

### 컨테이너 / 바이트코드 함정

`env-ai_worker-1`은 `worker` bind mount + **별도 `__pycache__` 볼륨**.  
소스만 고치고 restart 했는데 옛 동작이면:

```bash
docker exec env-ai_worker-1 find /app/ai_worker -type d -name __pycache__ -exec rm -rf {} +
docker restart env-ai_worker-1
```

Java(`ExternalJobRequest`) 변경은 **backend 이미지 rebuild** 필요 (`docker compose up -d --build backend`).

## 7. 버그·시행착오 타임라인 (학습용)

| 증상 | 원인 | 수정 |
|---|---|---|
| 장면마다 음량 들쑥날쑥 | 장면별 Fish 재합성 | 통합 wav + 분할 재사용 |
| 텍스트/음성 싱크 불일치 | 글자 수 추정 또는 오디오 지연 | actual-word alignment, 150ms visual lead (오디오 adelay 금지) |
| adelay 후 “먹히는” 소리 | 오디오 선무음 | adelay 제거 |
| 클로징 text/첫 음절 간격 불일치 | cached/generated WAV의 선행 무음 편차 | PCM `-45 dBFS`/3-frame 측정 후 부족분만 pad, 250ms prior hold + 500ms tail |
| 본문 4초만 / 잘림 | silenceremove가 호흡을 절단 | silenceremove 제거 및 새 캐시 버전 적용 |
| 본문 중간 완전 무음 | `-ss` after `-i` + `afade` | forced-alignment start 기반 `atrim`, 무 fade |
| static mux 조기 종료 | ffconcat terminal duplicate가 final `-t`에서 제외됨 | terminal PNG 미중복 + `tpad=stop_mode=clone:stop=-1` + final audio cap/CFR 30fps |
| 댓글도 yura | again_spring 전구간 voice lock | 본문만 lock, comment pool |
| 재생성해도 옛 영상 | WB 중복 ingest (RENDERED) | FAILED 강제 또는 externalId 변경 |
| origin_id too long | `__cv_manbo-manu` 등 | `__cv_{sha8}` + VARCHAR(128) |
| 코드 반영 안 됨 | `__pycache__` 볼륨 | pyc 삭제 후 restart |
| FHD에서 댓글/outro 누락 | legacy `HD_RENDER`가 ScriptData를 15-frame으로 재구성 | `composer.py`가 canonical SceneDirector SD를 atomic stream-remux; HD job `87` DONE |

검증 이력 예시: `#436` 통합낭독, `#441` 댓글 보이스, `#447` silenceremove 사고, `#449` 26-line actual alignment confidence `1.0`, `#454` 이전 renderer 운영 렌더가 있다. 최종 기준은 **ASM `01KZ837XTDDX2P2MG90N42BM53` / WB post `10022894`**다. 이 잡은 1080×1920/CFR 30fps, 1710 frames, video `57.000000s`, audio `56.991995s`, delta `8.005ms`로 통과했다. FHD 누락은 `atempo`가 아니라 legacy `HD_RENDER` 15-frame rebuild가 comment/outro를 빠뜨린 문제였고, canonical SD atomic stream-remux로 수정해 HD job `87` DONE을 확인했다.

## 8. 다음 개선 제안 (다른 LLM용 백로그)

우선순위 제안:

1. **합법적 참조 음성 녹음 확보**
   현재 확인된 Yura reference는 1개뿐이다. 화자 동의와 정확한 원고를 함께 보관한 8~12초
   WAV 녹음이 제공되기 전에는 추가 reference 등록을 진행하지 않는다. 제공 뒤 `prepare_voice.py`
   등록 및 재감사를 수행한다.

2. **정렬 폴백 청감**
   ASR confidence가 `0.55` 미만이거나 alignment 모델 로드에 실패하면 장면별 TTS로 폴백한다. 이 경우의 실제 음성 품질과 전환 청감을 컨테이너 preview로 확인한다.

3. **Instagram Reels**
   `instagram_reels`에 `tts_voice`만 있음. Shorts와 동일 WB 렌더를 reels 타깃으로 연결할지 제품 필요.

4. **AS prod FE**
   댓글 TTS 피커는 **dev에 반영**. prod 어드민 UI는 prod 배포 지시 후. 현재 prod는 ASM API로 `comment_tts_voices` 설정됨.

5. **캐시 무효화 API**
   “재렌더”를 FAILED SQL 없이 하는 admin/WB 엔드포인트.

6. **e2e**
   Shorts는 LLM/GPU 의존 → realbe에서 스모크 범위 합의 필요. LLM 호출 금지 규칙 주의.

7. **메타포 intro**
   `metaphor_id` PNG intro (이미 연결됨). 카탈로그·PLAN 매칭은 AS 쪽 이전 작업 참고.
